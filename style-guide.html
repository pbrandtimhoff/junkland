The Propeller style guide

Everything you need to build the restyled propeller.la. Fonts first, then colour, type scale, components and the copy rules. All values here are the real ones from the prototype, so you can copy them straight across.

1 · Fonts

Three faces, three jobs. Never mix the roles - the whole look depends on the split between a condensed uppercase display face, a neutral body face and a mono for small labels.

Display · Oswald · weights 400 500 600 700
Do good. Win big.

Every headline, button label, stat number and card title. Always uppercase, line-height 1.0-1.13, letter-spacing about -0.01em on big sizes. Weight 700 for headlines, 600 for card titles.

Body · Inter · weights 300-800
All running copy, form fields, descriptions and paragraphs. Sentence case, 15px base, line-height 1.55. Use weight 500 for secondary copy on light backgrounds so it does not go muddy.
Labels · Space Mono · weights 400 700
Eyebrows · statuses · metadata · 0.18em tracking

Small uppercase labels only: eyebrows above headlines, status pills, timestamps, counts, table headers. 10-11px, letter-spacing 0.14-0.22em. Never use it for body copy.

Paste this into the head

<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Oswald:wght@400;500;600;700&family=Inter:wght@300;400;500;600;700;800&family=Space+Mono:wght@400;700&display=swap">
/* font tokens */

⚠ Decide before Hannah starts: Oswald or the licensed face?

The prototype uses Oswald (free, Google Fonts) as the display face, matching the partner portal. The legacy propeller.la marketing site uses Aktiv Grotesk Condensed, with Balboa 900 as its substitute, both via Adobe Typekit kit lrp5ong.

These are not interchangeable and swapping later means re-tuning every headline size. Confirm with Brandon which one ships, then Hannah builds against it once.

Resolved · every page is now on the three-face system

how-it-works-v2.html was the last outlier (Anton + Space Grotesk, hard "sticker" borders). It has been converged to Oswald + Inter + Space Mono with the soft-card chrome, so you can treat all pages as consistent.

Where the gradient goes

  • Do use it on primary buttons, one or two words of a headline, thin progress bars, small badges and stat numbers.
  • Don't fill a whole section background with it, run it behind body copy, or animate its colours. We tried the shifting-gradient text and cut it.
  • Do use --pg-btn (amber swapped to #FF8400) instead of --pg specifically when the gradient fills a button — .btn-fill, .btn-grad, .btn-premier, .btn.golden, .btn.premier-pill, .go-premier and .redeem all use it. Headline text, badges, dots and stat numbers keep the original --pg amber.

Imagery

  • Photos sit under a dark gradient scrim whenever text sits on them. Never place white type straight onto a photo.
  • Experience artwork is square and never cropped - those graphics already carry their own title lockup, so don't add a headline over them. Pull them live from the propeller.la CDN (/cdn-cgi/image/...) so they stay current.
  • Cause and action cards use 16/11 media with the type tag top-left and the nonprofit logo chip bottom-left.
  • Winner photos show the winner with the artist. Never split or collage them.
⚠ The action-page photos are placeholders

On action.html, the hero and in-card photos are winner meet-and-greet and festival shots chosen for tone, not subject - some have an artist name visible in frame. That is fine for a design review and wrong for anything live. A meet-and-greet photo is not a photo about voting rights or mental health.

Before these ship, they need real cause photography - the fastest source is the partner nonprofits' own approved libraries (HRC, Trevor, Feeding America all have them). Every image is overridable per action with ?img=. Same gap on the "earn more" cards.

5 · Action pages

action.html renders every action type from URL params (?type=). Two things make these feel like Propeller rather than a form.

The stage is cosmic

  • Deep-space background: near-black ground, a per-type accent glow up top so each type keeps its own colour, soft wide nebula, and two parallax starfield layers. Pure CSS, no images.
  • Petitions are the exception - they stay dry. No starfield, one restrained wash, a sober gradient. Serious asks shouldn't sparkle. The per-type hook is body.t-<type>, so any type can be toned up or down.
  • Watch runs in a pure-black cinema mode. Discover is a multi-step Duolingo-style lesson, not a single card.

Every action feeds a sweepstakes

This is the whole difference from a change.org or a generic petition tool, and the layout has to show it.

  • Lead with the experience: an eyebrow chip ("Win a VIP trip to...") and a CTA that reads "earn 25 entries", not just "+points".
  • Include a "what this action enters you to win" block with the real experience artwork and the prize package.
  • Built to be scanned, not read. The ask and the sign/submit action sit high; supporting detail (who you're telling, why it matters as numbers, who started it, what happens next) sits below; the formal/legal text collapses one tap away. Never open on a wall of body copy.
  • On any entry surface, keep the AMOE / no-purchase line visible - it's required. Everything else legal can live in the collapsed drawer.

6 · Icons

The prototype uses inline SVGs and a few emoji placeholders. The real set is Brandt's to build - the full running spec, priorities and naming live in ICON-LIBRARY.md in the repo. Don't invent one-off icons per page; pull from that library so the whole site shares one vocabulary.

  • Feature icons follow the animated gradient "puck" look already used on Premier (assets/premier/*.gif).
  • Flat UI icons are single-colour SVG on a 24×24 grid using currentColor - no baked hex.
  • Deliver on true transparency so the same file composites on both light and dark.

7 · Motion

  • Transitions are .15-.18s ease. Anything slower feels sluggish on a phone.
  • Scroll reveals fade up ~20px, once, via IntersectionObserver. Never re-animate on scroll back.
  • Every animation sits behind @media (prefers-reduced-motion: reduce). This is not optional.
  • Large blur radii are the expensive part on mobile. Cut blur and opacity under 640px.

8 · Copy rules

These are hard rules, not preferences. They apply to everything user-facing.

  • Hyphens, never em dashes. This one is absolute for anything the community sees.
  • Never the "not X, it's Y" construction. Also avoid "not just X but Y". It reads as machine-written.
  • Always pro-something, never anti-anything.
  • The brand is Propeller, never "propeller.la" in copy. URLs in links are fine.
  • Say "actually show up", not "give a damn". The latter is retired everywhere.
  • All-Access is the Premier shorthand: "Get All-Access with Propeller Premier."
  • Don't literally use the word "identity". Show it through attitude, never announce it.
  • Use the nonprofit's own words for cause copy. Never invent a cause claim or a statistic.
  • Lead with bold short statements. If a paragraph needs three sentences to make its point, it is the wrong paragraph.

9 · Mobile first, always

90%+ of traffic is mobile

Design and check the phone layout before the desktop one. Breakpoints in the prototype are 820px (tablet, drop to two columns) and 560px (phone, single column, full-width buttons).

The one thing that catches everyone: use overflow-x: clip on the body, not hidden. hidden turns the body into a scroll container and silently breaks every position: sticky element on the page.
